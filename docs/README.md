# Go Fiber Template API Documentation

This directory contains comprehensive documentation for the Go Fiber Template API, including interactive Swagger documentation, detailed examples, and testing guides.

## 🚀 Quick Start

### 1. Interactive API Documentation (Recommended)

The **fastest way** to explore and test the API is through the built-in Swagger UI:

```
🌐 http://localhost:8080/swagger/
```

**Features:**

- 📖 Complete interactive documentation
- 🧪 Test endpoints directly in browser
- 🔐 Built-in authentication support
- 📋 Real request/response examples
- 🔍 Schema validation and examples

### 2. Authentication Quick Start

1. **Open Swagger UI** → `http://localhost:8080/swagger/`
2. **Register/Login** → Use `POST /auth/register` or `POST /auth/login`
3. **Authorize** → Click "Authorize" button, enter `Bearer {your-access-token}`
4. **Test Endpoints** → All protected endpoints now work automatically

### 3. API Base URL

```
http://localhost:8080/api/v1
```

| Method | Endpoint         | Description                        | Auth Required |

## 🔐 Authentication System

The API uses **JWT (JSON Web Token)** for secure authentication:

### Token Types

- **Access Token**: 15 minutes expiration (for API requests)
- **Refresh Token**: 7 days expiration (for getting new access tokens)

### Header Format

```
Authorization: Bearer {your-access-token}
```

### Authentication Flow

1. **Register/Login** → Get access_token and refresh_token
2. **Use Access Token** → Include in Authorization header for protected endpoints
3. **Refresh When Needed** → Use refresh_token to get new access_token
4. **Logout** → Invalidate both tokens

## 📄 Pagination & Filtering

### Pagination Parameters

- `page` - Page number (default: 1, minimum: 1)
- `limit` - Items per page (default: 10, minimum: 1, maximum: 100)

### User Filtering Parameters

- `search` - Search in first_name, last_name, and email
- `is_active` - Filter by active status (true/false)
- `sort_by` - Sort field (id, email, first_name, last_name, is_active, created_at, updated_at)
- `sort_order` - Sort direction (asc, desc)

### Example Request

```
GET /users?page=2&limit=20&search=john&is_active=true&sort_by=created_at&sort_order=desc
```

## ⚠️ Error Handling

### HTTP Status Codes

| Code  | Status                | Description                            |
| ----- | --------------------- | -------------------------------------- |
| `200` | OK                    | Request successful                     |
| `201` | Created               | Resource created successfully          |
| `400` | Bad Request           | Invalid request or validation errors   |
| `401` | Unauthorized          | Invalid/missing/expired authentication |
| `403` | Forbidden             | Access denied                          |
| `404` | Not Found             | Resource not found                     |
| `409` | Conflict              | Resource already exists                |
| `500` | Internal Server Error | Server error                           |

### Error Codes

| Code               | Description               | Common Causes                                 |
| ------------------ | ------------------------- | --------------------------------------------- |
| `VALIDATION_ERROR` | Request validation failed | Invalid email format, missing required fields |
| `UNAUTHORIZED`     | Authentication failed     | Invalid credentials, expired token            |
| `NOT_FOUND`        | Resource not found        | Invalid user ID, deleted resource             |
| `CONFLICT`         | Resource conflict         | Email already registered                      |
| `INTERNAL_ERROR`   | Server error              | Database connection, unexpected errors        |

## 🔧 Development

### Regenerate Swagger Documentation

```bash
# Install swag if not already installed
go install github.com/swaggo/swag/cmd/swag@latest

# Generate documentation
swag init -g cmd/server/main.go -o docs
```

### Update Documentation Workflow

1. **Update Swagger Comments** in controller files (`internal/controllers/`)
2. **Run Documentation Generation** with `swag init`
3. **Update Example Files** in `docs/examples/` as needed
4. **Test Documentation** via Swagger UI

### Documentation Comments Format

```go
// @Summary Brief endpoint description
// @Description Detailed endpoint description with examples
// @Tags TagName
// @Accept json
// @Produce json
// @Param paramName paramType dataType required "Parameter description"
// @Success 200 {object} ResponseType "Success description"
// @Failure 400 {object} ErrorType "Error description"
// @Router /endpoint [method]
// @Security BearerAuth
```

## 🆘 Support & Troubleshooting

### Common Issues

1. **🚫 Server not responding**

   - Ensure server is running: `go run cmd/server/main.go`
   - Check port 8080 is available
   - Verify environment variables are set

2. **🔐 Authentication errors**

   - Check token format: `Bearer {token}` (note the space)
   - Verify token hasn't expired (15 min for access tokens)
   - Use refresh token to get new access token

3. **📄 Documentation not updating**
   - Run `swag init -g cmd/server/main.go -o docs`
   - Restart the server
   - Clear browser cache
